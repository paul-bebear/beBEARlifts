Written 2026-10-21 against `master` at 07e06e22, the 49 fork commits after 7eef7634. Read-only.

Six parallel reviews were merged: security, data, workout correctness, iPhone, product, code health. The items that drive the top list were re-read in the source. ## Fix before inviting testers

Ordered by harm.

1. The first workout on a new phone, or in a Safari tab instead of the Home Screen app, overwrites the cloud backup with a one-workout file. Nothing reads the seven weekday copies. Proven by a scratch test against the real thunk. See D1.
2. Effort rating writes 6, 8 or 10 into `completedRpe`, which the estimated 1RM, the PR banner, the 1RM graph and the history colours all read. "Just right" on the same lift gives a new PR and a 6.5 percent graph jump. It is on by default. See W1 and W2.
3. Anyone with any email address can open an account, and the AI cap is 60 calls per account per day. Sign-up is open on the live project (`disable_signup: false`). Spend is bounded only by the dashboard email rate limit. See S1.
4. Every fork store that fails one read starts empty and the next write replaces the stored data. Four stores also never report a failed write. A truncated `bebear_foodlog` loses months of food entries with no message. See D2 and D3.
5. Four day-one dead ends: Friends "Open Settings" does nothing, the Home checklist "Log your weight" does nothing, every tab bounces to the program list while no program is picked, and a tester without an invite link sets the app up in the Safari tab and loses it when they add the icon. See U1 to U4.
6. Delete account returns 500 on production: `SUPABASE_SERVICE_ROLE_KEY` is not set in Vercel. Verified live. See S2.
7. The warmup is stored under workout id 0, so every workout shows the previous workout's warmup with its ticks. See W3.
8. A song that was playing when the phone locked is marked skipped even when Spotify's history says it played to the end. The phone is locked between most sets. Proven by a scratch test. See W4.
9. A run keeps counting moving time while the phone is locked, so pace after a lock is wrong and saved that way. Proven by a scratch test. See W5.
10. The invite flow creates a profile named "Lifter @lifter_<13 characters of the user id>" without asking, and typing a handle can accept a stranger's pending request with no Accept tap. Spotify's 5-user cap fails silently for tester 6. See S3, U5 and U6.

- **S1. Open sign-up plus a per-account AI cap leaves AI spend unbounded**
  - Severity: high. Blocker if the AI Gateway has no spend cap, which is a dashboard setting this review could not read.
  - File and line: `src/utils/cloudBackupClient.ts:24` (`create_user: true`), `supabase/migrations/20261020221250_ai_usage.sql:29-36`, `api/_auth.mjs:6` (`defaultDailyCap = 60`), the four callers at `api/ai/onboard.mjs:81`, `api/ai/report.mjs:44`, `api/ai/warmup.mjs:50`, `api/food/photo.mjs:78`.
  - Scenario: an abuser scripts `POST /auth/v1/otp` with the public key for addresses they control, verifies the codes, then calls `/api/ai/onboard` 60 times per account. One onboarding call sends the four prompt files (about 22,000 tokens) plus up to 6 images and allows 12,000 output tokens, about $0.01 per call on Haiku 5.5. With Supabase's default 30 emails an hour that is about 720 accounts a day, about $430 a day. The functions send no CORS headers, which stops browsers on other sites but not curl.

Set a spend budget on the AI Gateway and a Vercel Firewall rate limit on `/api/ai/*` and `/api/food/photo`.
  - Effort: 2 hours for the SQL ceiling and the sign-up switch, 1 hour for the firewall rule.

## Data integrity

- **D1. The first workout on a new phone overwrites the cloud backup with a one-workout file**
  - Severity: blocker. Proven by a scratch test against the real `Thunk_cloudBackup` with the stubs `test/cloudBackupThunks.test.ts` uses.
  - File and line: `src/models/cloudBackup.ts:64-69` (`CloudBackup_isAutoDue` is true when `lastBackupAt == null`), `src/utils/supabaseClient.ts:50-54` (`lastBackupAt: undefined` on a phone that had no session), `src/ducks/thunks.ts:1786-1794` (uploads whatever `getState().storage` holds), `src/utils/cloudBackupClient.ts:46-63` (writes `latest.json` then today's `day-N.json`, no remote check), `src/components/cloudBackupAfterWorkout.tsx:6-8` (runs on every finish screen).

They sign in, do not tap "Restore from cloud", and finish one workout. The finish screen uploads a file with 1 workout to `latest.json` and to today's weekday file. While that flag is set, make `update` reject with "Could not read saved data" and retry the read on the next call. On a parse failure, copy the raw string to `<key>_unreadable` before any write. Fold the four hand-written stores into `JsonStore_create` so the fix lands once (see C1).
  - Effort: 2 to 3 hours.

## Correctness of the workout features

All 178 fork tests in this area pass. The findings below come from reading and from scratch tests.

- **W1. Every effort rating raises the estimated 1RM, so "Just right" alone produces PR banners and graph jumps**
  - Severity: high. Proven by a scratch test with `Weight_getOneRepMax`.
